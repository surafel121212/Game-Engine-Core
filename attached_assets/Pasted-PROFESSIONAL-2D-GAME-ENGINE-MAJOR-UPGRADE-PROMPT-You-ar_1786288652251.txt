PROFESSIONAL 2D GAME ENGINE — MAJOR UPGRADE PROMPT

You are upgrading an existing C++ 2D game engine.

DO NOT rebuild the project from scratch unless absolutely necessary.

FIRST inspect the existing repository and understand the current architecture, implemented systems, build system, Android runtime, editor, renderer, scene system, asset system, and scripting system.

Then upgrade the existing engine into a much more professional, complete, Android-focused 2D game-development environment.

The final result should feel like a serious 2D game engine/editor rather than a prototype.

Do not remove working features.

Do not break existing projects.

Preserve backward compatibility where reasonably possible.

Implement features instead of creating fake buttons or placeholder panels.

Every editor control should be connected to real underlying engine functionality.

1. PROFESSIONAL SCRIPTING SYSTEM

This is one of the highest priorities.

Create a complete and professional scripting architecture.

The engine must allow game developers to create gameplay without modifying the engine's C++ source.

Use Lua as the primary high-level scripting language.

The scripting system must support:

- Script assets
- Script components
- Script attachment
- Script detachment
- Script creation from editor
- Script editing
- Script execution
- Script reload
- Script lifecycle
- Script properties
- Script variables
- Script events
- Script error reporting
- Script debugging
- Script API documentation
- Script-to-engine communication
- Engine-to-script callbacks

Support lifecycle callbacks:
